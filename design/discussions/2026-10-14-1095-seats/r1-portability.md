Codex’s September “hooks unverified” row is superseded by the adapter and current documentation. Its end hook has a maximum three-second timeout and does not run for subagents. Hooks also require trust. These are convenience boundaries, unsuitable as the sole cleanup guarantee. [Official hook documentation](https://learn.chatgpt.com/docs/hooks)

Across all three, Stop/agent completion is **not task completion**. Crashes and SIGKILL cannot guarantee shutdown callbacks. Resume restores conversation state, not deleted temporary files. The route launch doors include independent headless Claude/Pi processes and `codex exec`; Pi children can deliberately have no saved session. None exposes a universal “this task and every consumer have finished” signal.

**Option A — portable with caveats**

The portable core is plain Git registration plus task-owned storage. Existing `hunt` creates trees under `<primary>/.claude/worktrees/t…`; that directory name does not make the mechanism Claude-dependent.

Concrete failures:

- **Claude:** `ExitWorktree` is not universally available and has ownership restrictions documented in `roar`. Native subagents may share parent scratch; child completion cannot authorize parent-directory deletion.
- **Codex:** read-only seats cannot create `.tmp`, update excludes, or remove trees. Under workspace-write, `.tmp` inside the selected workspace is suitable, but shared Git metadata and sibling trees can lie outside writable roots. Creating a tree does not automatically establish access to it; launch into it with `-C` or configure permitted roots. Native `--worktree` needs characterization before lifecycle claims.
- **Pi:** plain Git creation does not retarget the parent’s tool cwd. Its bash overflow files are generated by the Pi process using Node `os.tmpdir()`: setting `TMPDIR` inside an individual bash command does **not** relocate those parent-generated `pi-bash-*.log` files. The inspected output-file helper supplies no deletion lifecycle.

Shared defects:

1. **The proposed WIP preservation claim is false with current ordering.** `worktree-gc.sh` purges `.panel` and `build/panel-head` before `report_wip`. `worktree-exit-preflight.sh` does likewise. Adding `.tmp` there would delete it even when other WIP subsequently blocks removal.
2. GC snapshots Linux `/proc/*/cwd`; it does not inspect open files. A consumer operating from elsewhere can be invisible. PID locks also require a genuinely long-lived owner; hunt’s `$PPID` assumption needs validation under wrappers and Codex’s server architecture.
3. `[gone]` means the upstream disappeared, **not proof of merge**.
4. Main-checkout `.tmp` has no cleanup lifecycle. Calling it small is inference.
5. Moving bytes off tmpfs changes the exhausted filesystem; it does not prevent disk exhaustion.

**Fix:** make plain-Git creation, explicit workspace paths, ownership/locks, and task-close cleanup canonical. Inspect WIP before deleting `.tmp`; preserve tracked contents and required evidence, verify completion/ancestry separately, and retain on ambiguous liveness. Provide a per-task namespace and explicit close operation outside worktrees too. Runtime hooks may remind or invoke that operation opportunistically.

**Option B — portable with caveats**

A registered task root can work independently of runtime sessions, but the proposed liveness transplant is insufficient.

- **Claude:** session UUID visibility does not establish ownership of an arbitrary task root, especially with shared scratch and detached workers.
- **Codex:** the read-only launch door cannot allocate the root. External `${TMPDIR}` paths need permitted writable roots; merely setting the environment variable does not grant filesystem access.
- **Pi:** registering a root does not capture parent-generated bash logs or extension prompt temporaries. Command-local `TMPDIR` reaches child tools, not the parent runtime.
- **All:** task IDs can collide between concurrent runs; PID reuse, remote hosts, inaccessible `/proc`, and paused resumable sessions defeat “no live process” reasoning. A fifteen-minute age rail delays deletion but proves neither abandonment nor evidence disposal. An unregistered worktree can still contain valuable WIP.

**Fix:** use unique run identities, atomic ownership records, host/process-generation identity, explicit completion and evidence-retention state, and fail-closed recovery. Age may supplement those conditions, never replace them. Select a writable base explicitly and keep runtime-native output management separate.

**Option C — portable with caveats**

Report-only inspection is portable across these runtimes and safely preserves everything. It is incomplete lifecycle management.

- **Claude:** “use scratchpad” embeds Claude’s managed layout and end-hook behaviour.
- **Codex:** has no demonstrated equivalent managed scratchpad; read-only seats cannot implement the directory rule.
- **Pi:** runtime bash logs continue outside task directories.
- **All:** top-level `/tmp` reporting misses custom `TMPDIR`, cache roots, and worktree storage. Reboot recovery is host-specific and can destroy required evidence.

**Fix:** use the same runtime-neutral task-storage contract everywhere and report its configured roots alongside `/tmp`. Keep deletion explicitly ownership/evidence-aware. Treat C as an observability companion, not the solution.

**Excluded `.tmp` and worktree removal**

Git semantics predict that an untracked, excluded `.tmp` is hidden from `status --porcelain --untracked-files=all`; `all` expands untracked paths, not ignored paths. Already tracked files remain visible. A successful ordinary `git worktree remove` should delete the ignored directory with the tree—**prediction, not locally tested**.

The settling experiment is a serial throwaway repository test: exclude `/.tmp/` in common `info/exclude`, populate it in a linked worktree, verify empty status and ignored status, then remove without force and check both directory absence and registration removal. Controls: no exclusion; a tracked modified `.tmp` file; real WIP plus `.tmp`; live cwd and live lock. Configure an upstream-gone branch for GC cases. The WIP control must assert that `.tmp` survives, directly testing the ordering defect.
