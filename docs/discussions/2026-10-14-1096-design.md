## The problem in one paragraph

A single ticket's PR passes through up to three review orchestrators: hunt
runs the review-pr loop for up to three rounds (`skills/hunt/SKILL.md:117-133`);
raid then runs gaze on every MR (`skills/raid/SKILL.md:282-289`), which starts
its own battery: adherence, native `/review`, review-pr again through
`agents/gaze-pr-review.md`, simplify and the gate
(`skills/gaze/SKILL.md:227-232`, `:446-470`). Review-pr infers "what was
already reviewed" from a count of its own posted reviews
(`skills/review-pr/SKILL.md:208-218`), never from the revisions reviewed;
review-pr-prose copies its contract with "keep the two in sync"
(`skills/review-pr-prose/SKILL.md:157-171`).

## Round 1 options (architect)

- **A. One review skill with content modes.** `review-pr` keeps its name and
  takes `mode=code|prose|auto`; the prose panel becomes a reference file;
  review-pr-prose, the gaze battery and `agents/gaze-pr-review.md` are deleted;
  gaze becomes an alias; hunt owns the review plan; verify-gate gains a stale
  evidence check. ~35-45 files, three children.
- **C. Delete the second battery only.** Both review skills stay; both gain the
  evidence record and reuse rule; gaze becomes an alias. ~25 files, two
  children. Equal to A's first two children.
- **B. Separate helpers, hunt orchestrates.** `review-code` and `review-prose`
  as renamed helpers, plan logic in hunt, no router. ~45 files.
- The three-skill candidate (a `review` router over code and prose helpers)
  was not put forward: B plus a layer with no demonstrated need.

Shared core: one evidence record, a structured block in the review comment on
the MR (not a branch file, which would move the head; not `.git/`, which is
machine-local), and a deterministic reuse script grown from
`scripts/review-pr-anchor.py`.

### Round 1 assessments

**Portability (OpenAI family).** A, B, C and the core are portable *with
conditions*. Nothing may rest on hooks, Claude's `context: fork` notification
lifetime, or nested subagents; Pi core has no subagents (its example extension
spawns processes); Codex `exec` and `spawn_agent` work but a read-only child
cannot publish, so the controller must. Post-image blobs plus base
disjointness do not prove unchanged review meaning (modes, renames, deletions,
dependencies, criteria and policy can change). A mutable forge comment is a
claim that needs validated authorship. Mixed code and prose MRs need a
composed plan. Naming: Codex has a native `review` CLI command; Claude's
`/review` is documented in gaze but its current registration was not verified;
Pi binds none of `review`, `review-pr`, `gaze`. Correction to the architect:
gaze already offers a portable simplify (`skills/gaze/SKILL.md:561-576`).
B's defect is contractual: standalone helpers bypass the plan.

**Evidence.** The core would have helped on 1390's unchanged-head repeat and
#1334, and replaces the hand blob checks of the 1389/1390 gates; it changes
nothing on JETP #152/#154. Risk: #1377 shows an approving seat can be wrong on
a head another seat catches, so reuse is safe only if the plan still buys
red-team or another family at that risk row; #1334 shows reuse must never cover
gate and check results. A's prose fold is little used (3 vs 336 on padme; 13 vs 501 on both hosts after the doudou census). C captures
nearly all measured repeat savings. No episode favours B. The architect's
10-25 min per MR estimate is unsupported.

**Values (simulated).** Accepts the blob keying; integrity objections: the
forge comment is editable, file-granular scope misses context files, and
`reused` must be visible in the gate verdict. An inherited cross-family seat
must not silently count as independent at the high-risk row. Leans to A
sequenced as C first, with the reuse rule in one shared script from day one,
and timings measured before any window is claimed. Rejects B and the
three-skill router.

## Round 2: two surviving designs

Common to both (architect, revised):

- **Benefit restated.** The 10-25 min claim is withdrawn. A separate
  reliability effort (startup, timeouts, isolation guard) is needed for the
  20-minute goal.
- **Evidence record**, per seat, in a structured forge comment block: forge
  and repository identity, base and head SHAs, `git patch-id --stable` of
  `base...head` plus `git diff --raw -M`, the context paths each seat read,
  an exit-criteria hash, a policy version, producer and reviewer identity,
  family, effort and transport, hashes of published reports, and check,
  adherence and gate results each keyed to its head. Edited, malformed or
  unreadable blocks fail closed with a one-line fix message. The controller
  publishes; seats return text only.
- **Reuse rule**, one script (`scripts/review-evidence.py`): a seat is reused
  only if it ran and approved, the patch-id and raw diff are identical, the
  base moved without touching its scope or context paths, and the criteria
  hash and policy version are unchanged. Never reused across heads: check and
  gate results (#1334) and adherence.
- **Risk rows.** The high row always includes red-team and one other-family
  seat (#1377). An inherited other-family seat counts there only with an
  identical patch-id and context, printed `independent: inherited from <head>`.
  Replication becomes a named, priced plan entry.
- **verify-gate** adds a seat table (ran, reused with origin head, no-report)
  and an independence line; stale or unproven evidence is REROLL; a required
  no-report is ESCALATE. Merge stays the caller's decision.
- **Native `/review` and `/simplify`** become optional adapter seats; simplify
  is a declared seat with status native, portable or none; portable simplify
  is required for code at the ordinary row and above.
- **Gaze** becomes an alias (continue hunt's plan, then verify-gate) that adds
  no battery, kept one release then deleted. **Raid** phase 6: rebase,
  continue hunt's plan, gate.

### Design C: delete the second battery, one shared reuse script

Hunt owns the plan and runs verify-gate at the end. review-pr and
review-pr-prose both call the shared script and become transport-neutral
(capability discovery instead of a check for the Agent tool). Deleted: the
gaze battery and tier tables, `agents/gaze-pr-review.md`,
`skills/gaze/telemetry.yml`. Per-phase timings go in the evidence block.

- **Price:** two child PRs (~6 and ~14 files); ~7 agent-hours; ~1.25
  author-hours. Review spend roughly flat (other-family seats still bought at
  the high row).
- **Residual risk:** the code/prose naming clash is justified, not resolved;
  two panel bodies can drift in panel policy.

### Design A: one review skill with modes = C plus a prose fold

As C, then a third child: `mode=code|prose|both` with `auto` resolving a mixed
MR to `both` (code seats on code paths, prose seats on prose paths, one gate);
the prose panel moves to `skills/review-pr/references/prose.md`;
review-pr-prose becomes an alias, then is deleted.

- **Price:** third child ~12 files, ~3 agent-hours, ~0.75 author-hours; total
  ~10 agent-hours, ~2 author-hours.
- **Residual risk:** `both` is new logic on a rare path with zero past
  episodes to test it on; the value is one contract and the naming, not time.

Design B was dropped: no episode shows it helping, it costs the most and it
needs the same shared script to be safe. No seat defended it.

### Round 2: remaining objections

**Portability (OpenAI family).** C and A remain portable with conditions; no
remaining architectural objection to either.
- C: both panels must lose their Claude-specific fork and polling assumptions
  and reviewer-written report paths (`skills/review-pr/SKILL.md:40-75`), and
  consume the same executable plan and policy, not only the same parser.
- A: `both` answers round 1; path partitioning may miss code and prose
  interactions (inference), so assign cross-cutting context explicitly and
  test mixed composition, standalone invocation and both aliases. A gives no
  stronger runtime guarantee than C.
- Authorship and "never edited" are observable through `gh api graphql`
  (`author`, `lastEditedAt`, `editor`) from any of the three runtimes' controllers:
  pin the expected forge actor ID; body-declared identity or
  `authorAssociation` is insufficient; API errors mean invalid evidence. Live
  check blocked by the sandbox's network; `gh 2.102.0` installed.
- `git patch-id --stable` ignores whitespace and line numbers: use it for
  candidate matching only; identity needs a canonical NUL-delimited raw diff
  with full object IDs, modes, paths, fixed rename settings, external diff and
  textconv disabled, and the recorded merge-base.
- "Paths each seat read" misses what it should have read: add declared
  dependency scope, invalidation on new relevant files, and a policy identity
  that covers profiles, routing and decorrelation requirements and project
  rules. Report locations must be retrievable and hash-verified.
- No remaining objection to controller publication, capability discovery
  (which must prove transport, collection, permissions and worker identity)
  or the qualified naming (Claude `/review` remains documentation-derived).

**Evidence.**
- Nesting: removing gaze's level is not contradicted but not supported as a
  rate change: nesting explains about 3 of about 15 degradations, the
  isolation guard 7. Do not claim a rate change.
- Authorship: the "expected controller account" rule would have rejected the
  reviews on 1389 (2) and 1390 (1), posted as the author's account, while JETP
  #152 was posted by the harness account. Needs an allow-list or a signed block.
- Controller-collects is a single point of failure, and in 1390 the controller
  was what failed (exit 124). Without the reliability work, C moves the wait.
- Context paths must be computed per seat by a named party, or the 1390
  scoped repeat recurs.
- The policy version must name which files count, since 1096 itself edits the
  review skills and every such edit would invalidate all reuse.
- A: defer; no mixed code and prose MR was found that needed `both`.
- Timing: the dominant 1389/1390 slices are already recoverable from Codex
  UUIDv7 ids; instrumentation must also timestamp failed attempts, which have
  no ids today.

**Values (simulated).** Round-1 objections answered and accepted.
- C: add a CI test that both review skills call the shared script with the
  same policy version (the prose path is the manuscript path, where drift is
  least noticed); include the reuse script's own hash in the policy version;
  the fail-closed message should name the command that regenerates the block.
- A: acceptable as a later third child, not as a precondition; keep the
  review-pr-prose alias until the next manuscript review actually runs through
  it, not one calendar release.
- At the high row, a reused seat's report hash must still resolve to a
  readable report at gate time, else it is no-report. Any other-family seat
  records its transport and worker.
- Missing question: human reviews posted outside the controller account must
  stay load-bearing comments (verify-gate non-negotiable 3), never reused
  seats, listed as `human: ran`.
- Lean (simulated): C now, with the script-hash and drift-test amendments.

## Agreement

- No automatic second battery on an unchanged diff; replication only as a
  named, priced plan entry.
- Hunt owns the review plan; raid coordinates tickets and merges; gaze becomes
  an alias that adds no battery, then is deleted.
- Check, gate and adherence results are never reused across heads.
- At the high-risk row, red-team and one other-family seat are mandatory.
- A required seat with no report means ESCALATE; no merge-with-recorded-gap
  path (simulated author agrees: integrity over the window).
- Native `/review` and `/simplify` are optional adapter seats, never the basis.
- No option rests on hooks, fork lifetime or nested agents.
- Design B and the three-skill router are rejected.
- 1096 does not deliver the 20-minute window; reviewer startup, timeouts and
  the isolation guard are the measured drivers.

## Remaining disagreements

- **C now or A in one go.** Architect, evidence and values (simulated) lean to
  C now and the prose fold only after a measured raid; A in one go remains the
  architect's second choice for an author who values one contract over
  waiting.
- **Who may post evidence.** Architect: the expected controller account only.
  Portability: pin the forge actor ID and check edit status via GraphQL.
  Evidence: a single account would have rejected the real reviews on 1389 and
  1390; allow-list or sign. An allow-list of pinned actor IDs satisfies both
  positions; it was not put back to the seats.
- **Diff identity and policy scope.** Portability wants a canonical raw diff
  for identity (patch-id for matching only) and a policy identity covering
  profiles, routing and rules; evidence warns that the wider the policy
  identity, the more often a raid that edits the harness invalidates all
  reuse. Where to draw the policy boundary is unresolved.
- **Value of the nesting reduction.** Architect counts it as a benefit;
  evidence finds it explains a minority of degradations.
- **Alias lifetime for review-pr-prose** (under A): one release (architect)
  versus until the next manuscript review uses it (values, simulated).

## Questions for the author

Prices are estimates from the architect's round 2, not measurements.

1. **Sequencing.** Do C now (two children), measure the next raid with the new
   timings, then decide the prose fold (A's third child)? And should the
   reliability work (startup, timeouts, isolation guard) become its own ticket,
   blocking the 20-minute goal rather than 1096? *Default: yes to both; this
   session files no ticket.* Price: C ~7 agent-hours, ~1.25 author-hours; the
   fold later ~3 agent-hours, ~0.75 author-hours; reliability work not priced
   here.
2. **Who may post review evidence.** *Default: an allow-list of accounts (the
   author's and the harness account), each block checked as unedited; human
   reviews stay load-bearing comments, listed as `human: ran`, never reused.*
   Alternative: signed blocks (more robust, more machinery). Price: inside C;
   signing adds ~2 agent-hours, ~0.25 author-hours (estimate).
3. **Independence at the high-risk row.** May an other-family seat inherited
   from an earlier head count as independent? *Default: only with an identical
   patch-id and context, a report still readable at gate time, printed as
   `independent: inherited from <head>`; otherwise it re-runs.* Price: no
   extra build; a re-run costs one cross-family seat (cents to tens of cents,
   per `skills/route/grid.json`).
4. **Native seats.** Retire native `/review` and `/simplify` as required
   seats, keep them optional, and require portable simplify for code at the
   ordinary row and above? *Default: yes.* Price: inside C.
5. **Names and aliases.** Keep `review-pr` (modes `code|prose|both` under A);
   gaze an alias for one release; review-pr-prose (under A) an alias until a
   manuscript review has run through the new mode. *Default: yes.* Price:
   none beyond C or A.

## Answers

Answered by the author on 2026-10-14, in this session, one question at a time.

1. **Sequencing: C now, plus a reliability ticket.** C is built first, the
   next raid is measured with the new timings, and the prose fold follows
   (see 5). Startup, timeout and isolation-guard reliability gets its own
   ticket, which blocks the 20-minute goal, not 1096. Not filed yet: the
   brief for this session said no new tickets.
2. **Evidence posters: an allow-list drawn from actual use, Copilot
   included.** At the author's request, all MinhHaDuong repositories pushed
   since 2026-07-14 were checked: 22 repos, 2,783 PRs, no query failed, M,
   `2026-10-14-1096-seats/evidence-review-authors.json`. Only three accounts
   posted reviews:

   | Login | Type | Reviews | Review-type comments | Repos |
   |---|---|---|---|---|
   | MinhHaDuong | User | 711 | 1,136 | 16 |
   | copilot-pull-request-reviewer | Bot | 184 | 0 | 6 |
   | copilot-swe-agent | Bot | 9 | 0 | 2 |

   The allow-list is these three forge actor IDs, pinned. Review blocks must
   still be server-reported unedited.

   The census corrects one round-2 claim. The evidence seat said JETP #152
   was posted by a separate harness account, but every review-type comment
   in the window came from MinhHaDuong. A single-account rule would
   therefore not have rejected any past review.

   Copilot posts formal reviews, never evidence blocks. Its model family is
   not exposed on the forge. The default proposed here, pending the author's
   confirmation: a Copilot review is admitted as a reviewer seat with family
   `unknown`, and it never satisfies the other-family requirement. Human
   reviews stay binding comments, shown as `human: ran`, and are never
   reused.
3. **Independence at the high-risk row: inherit only if identical.** This is
   the default as written: identical diff identity and context, and a report
   still readable at gate time. The gate prints `independent: inherited from
   <head>`. Otherwise the seat re-runs, and red-team is always required.
4. **Native seats: optional; portable simplify.** As written.
5. **Names: gaze becomes the single review skill (the author's
   proposition).** This replaces both "keep review-pr" and the gaze alias.
   - gaze runs hunt's plan, reuses valid evidence, starts no second battery,
     and takes `mode=code|prose|both`.
   - verify-gate remains the separate final check, and hunt runs it.
   - Timing: review-pr's code panel folds into gaze during C. The prose
     panel folds in after one measured raid, consistent with answer 1.
   - **No aliases.** review-pr is deleted when its panel moves into gaze,
     and review-pr-prose when the prose panel does.
   - **Lint the harness.** An adherence test fails on any live reference to
     a retired skill name. Live means `skills/`, `tests/`, `profiles/`,
     `agents/`, `adapters/`, `scripts/`, `rules/` and `README.md`.
     Append-only history is exempt: `memory/` (journal and evidence),
     `projects/*/memory`, `tickets/closed/`, `docs/reviews/`,
     `docs/discussions/` and dated design notes in `docs/`.

   Size, measured with `git grep -lw` over the live paths: 31 files cite
   `review-pr`, 20 cite `review-pr-prose`, and 41 cite `gaze`. Of the 158
   tracked files mentioning `review-pr`, most are history: 47 closed
   tickets, 20 journal entries, 17 per-project memory files and 27 under
   `docs/`. These are exempt from the rewrite and the lint. A first count of
   157, 56 and 337 included that history and was corrected the same day.
   The rename of 31 live files still trips the 15-file breaker, so it stays
   a child of its own. Revised estimate: about 9 agent-hours and 1.5
   author-hours for C, against about 7 and 1.25 before.
