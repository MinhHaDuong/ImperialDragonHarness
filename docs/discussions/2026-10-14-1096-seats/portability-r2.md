**Verdict: C and A remain portable with conditions. The revised evidence/reuse contract needs two further specifications.**

- **Design C:** No remaining architectural portability objection. The implementation must remove existing Claude-specific fork/polling assumptions and reviewer-written report paths from both panels and their profile contracts (`skills/review-pr/SKILL.md:40–75`, prose launch instructions). Claude Code cannot depend on nested `Agent`; Codex children may lack write permission; Pi delegation depends on an extension or separate processes. Remove the objection with explicit profile delivery, pinned revisions/cwd, bounded controller collection and transport-specific failure handling. Both panels must consume the same executable plan and policy, not just the same evidence parser.

- **Design A:** No remaining objection to explicit `code|prose|both`; mixed changes resolving to `both` answers round 1. **[Inference]** Path partitioning could omit interactions between code and prose. Remove that concern by assigning cross-cutting context explicitly and testing mixed-change composition, standalone invocation and both compatibility aliases. A offers no stronger runtime guarantee than C.

- **Forge authorship / “never edited”:** Observable through `gh api graphql` on suitably configured controllers in **all three runtimes**. Installed `gh 2.102.0` supports GraphQL. GitHub exposes comment `author`, `lastEditedAt`, `editor` and edit history. Specify the evidence object as an `IssueComment`, pin the expected controller’s forge actor ID, and require server-reported unedited status; body-declared identity, `authorAssociation` or timestamp equality alone is insufficient. Treat API errors, missing fields and uncertain edit status as invalid evidence. [GitHub schema](https://docs.github.com/en/graphql/reference/issues). **Live verification was blocked by network access**, so universal controller availability remains conditional. A shared controller account authenticates publication, not which runtime or reviewer produced it **[inference]**.

- **Diff identity:** `patch-id --stable` is suitable for candidate matching, not exact identity: it ignores whitespace and line numbers. [Git documentation](https://git-scm.com/docs/git-patch-id.html). The additional raw diff can close that gap **if** it contains full old/new object IDs, modes and paths. Specify a canonical, NUL-delimited, unabbreviated raw representation, consistent comparison endpoints and rename settings, and disabled external diff/text conversion. Plain `git diff --raw -M` leaves abbreviation/configuration ambiguity. Record the merge-base used for `base...head`; verify context content and base changes against the same endpoint convention.

- **Evidence/reuse:** No objection to per-seat reuse, fresh checks/adherence/gate, or visibly inherited independence. **[Inference]** “Paths each seat read” can miss dependencies the seat should have read, directory additions and changed project instructions. Add declared dependency/context scope, content identities and explicit invalidation for new relevant files. Policy identity must cover profiles, routing/decorrelation requirements and project rules, not only the panel skill. Specify report locations alongside hashes and require successful retrieval/hash verification.

- **Controller publishes artifacts:** No remaining objection. This directly supports read-only Codex seats and detached Claude/Pi workers. Publication failure or interrupted collection must leave incomplete evidence.

- **Capability discovery:** No remaining objection to replacing the `Agent` check. Discovery must establish usable transport, result collection, permissions and actual worker identity; an installed executable alone proves none of these.

- **Qualified naming:** No remaining objection to the revised qualifications. Installed Codex help confirms native `review`; Claude `/review` remains documentation-derived and unverified. Retain “no collision found,” scoped to inspected installations; Pi extensions and plugins prevent a universal absence claim. Skill names rather than literal slash commands are the portable contract.
