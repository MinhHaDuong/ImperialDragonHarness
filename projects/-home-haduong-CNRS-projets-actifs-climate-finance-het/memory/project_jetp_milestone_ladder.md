The programme ladder is defined in ticket 0725, section "Milestones after M1" (author, 2026-09-29): M2 = extraction pipeline that works on every document held (tracker 1500), M3a = discover to a cutoff date under a stopping rule and freeze the registry, M3b = extract, reconcile with CRS and IATI, join, release, M4 = operation (refresh, link-rot, launcher, Zotero store 1510, shared code for AEDIST).

**Why:** the author reframes a milestone by the kind of goal it serves: M2 is code, M3 is a scientific measurement, M4 is robust operation. Before 2026-09-29 "M2" meant live monitoring.

**How to apply:** a bare "M2" in a log entry or a closed ticket is the old live-monitoring train, not the extraction pipeline; log entries were left unrewritten on purpose (append-only). Separately, `conception/jetp-short-paper-framing-2026-09-15.md` uses M1/M2/M3 for analytical layers of the short paper, an unrelated scheme: do not read it as a programme milestone. Read 0725 for the current definitions rather than this note. Related: [[project-jetp-three-stages-m1a]].
