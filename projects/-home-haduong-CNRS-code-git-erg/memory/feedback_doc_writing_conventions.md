When editing PEP rationale prose, mark the passage with "GENERATED by Claude on TIMESTAMP" — design rationales always need human review.

When editing the spec (spec-erg-v1.md), the readership is agent-first, human-also. Note opportunities to align Go code literally on the spec text (as done with the Erg struct).

**Why:** Author considers PEP prose a judgment call that must be validated by a human, not rubber-stamped. Spec text is consumed primarily by agents parsing tickets, so clarity for machine readers matters most.

**How to apply:** Any PR touching PEP prose gets the GENERATED marker. Any PR touching the spec should flag code↔spec literal alignment opportunities in the PR description.
