Never end a report with an optional extra offered for his decision ("I could
also verify X — optional rather than owed", "want me to also…"). He answered
one such offer with two words: "no optional."

**Why:** an optional offer is work I have already judged not worth doing —
otherwise I would have done it. Handing it over anyway converts my judgement
into his attention, which is the scarcest thing in the loop, and it dresses a
non-decision as a decision. It is the same defect as a labelled option menu in
[[feedback_decision_briefs]], one level down: there the failure is refusing to
argue a real choice, here it is manufacturing a choice that was never real.

**How to apply:** before writing an offer, decide. Worth doing → do it and
report it done. Not worth doing → drop it silently, or record it in the ticket
log where it costs no attention. Reserve questions for decisions that are
genuinely his: a product call, an outward action needing authorization
([[feedback_execute_authorized_outward_actions]]), a partition boundary, a
trade-off where different readings lead to materially different work. "This is
optional" is the tell that it is none of those.

Corollary: a caveat honestly stated in a deliverable does not need a follow-up
offer attached. The issue #33 filing stated one mechanism conditionally because
it was reasoned rather than measured — that was correct and complete as
written; appending "I can firm this up if you like" added nothing but a
decision.
