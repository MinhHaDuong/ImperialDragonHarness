While merging a PR (2026-07-07, ticket 0014, `article-sept-costumes/`), an
untracked `het-refs.bib` sitting next to a tracked, cited `manuscrit.tex`
looked exactly like someone forgot to `git add` real hand-written content —
20 bib entries, no duplicates in the shared `refs.bib`, genuinely needed by
`\bibliography{../refs,het-refs}`. It was committed as source. The build
warning `Writing or overwriting file 'het-refs.bib'` on the next compile
revealed the truth: line 7 of `manuscrit.tex` was
`\begin{filecontents*}[overwrite]{het-refs.bib}` — the file is generated
fresh by LaTeX on every run; the `.tex` file is the actual source. Had to
`git rm --cached` it and gitignore it instead.

**Why:** an untracked file that a tracked file depends on is not
automatically "forgotten WIP" — it can be a build artifact the tracked file
*generates*. Committing it duplicates the source of truth and will drift.

**How to apply:** before adding an untracked file to git because a tracked
file references it, grep the tracked file for codegen markers
(`filecontents`, `\write`, `generated by`, a build script that writes that
exact filename) before concluding it's missing source. If found, gitignore
the generated file and fix the Makefile/build script to not list it as a
prerequisite (it won't exist before the first build pass — verify with a
simulated fresh-clone build: delete the file, run the build from scratch).
