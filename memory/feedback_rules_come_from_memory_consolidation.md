When a session surfaces a lesson that looks rule-shaped, save or update a memory
entry, and do not offer to edit `~/.claude/rules/` or project `.claude/rules/`
directly. Author, 2026-09-29, declining a proposed rule line after /roar step 11:
"No rule, I want them to come from consolidating memories."

**Why:** a single session's lesson is one observation; rules are promoted from
memories that have recurred and been consolidated (/dream promotion pass), so a
rule carries evidence from several sessions rather than one.

**How to apply:** at /roar step 11 or any "should this become a rule?" moment,
update the closest existing memory (check first: the lesson often already
exists, as the worktree-guard workaround did in
[[reference_git_in_a_worktree_session]]) and say it is there for /dream to
promote. Offer a rule edit only if the author asks for one.
