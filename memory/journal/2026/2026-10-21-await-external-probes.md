Portable wait design session, 2026-10-21 (session on padme, writer Sonnet 5.5, forked from the Stopguard session to own point 2: how an agent is notified when it waits on an external process, across Claude Code, Codex and Pi). The author's constraints were no token-burning polling, no wait loop that can run forever, and Pi as first-class.

The session produced a design for a homegrown waiter (a transient systemd user unit, one recorded outcome, delivery by live push, resume of a dead owner, or pull at the next prompt), then probed it. Probes on this host (Claude Code 2.1.306, Codex 0.163.0, Pi 1.3.0, systemd 255): `RuntimeMaxSec`, `$SERVICE_RESULT`, duplicate-name refusal and `--collect` behave as designed, with positive controls (clean exit, non-zero exit, SIGKILL). A unit survives a headless session exit on all three runtimes. Only Claude Code wakes the model when a background command exits; Codex background terminals finish without starting a turn, and Pi has no background tool. `codex queue` starts a turn in an idle plain TUI and, on a closed thread, runs the turn through the managed app-server daemon; from Codex's default sandbox it fails (embedded app server, read-only file system) and `systemd-run` fails on the bus. `codex exec resume` on a thread with an active writer is refused; `pi -p --session` against a session open in the TUI hung until timeout. Headless Claude Code hung on a bare `&` child until killed. Two first probes were invalid and redone (sleeps expired naturally; a crash control that exited 2 instead of a signal). Fable (Agent token `fable`) was asked about registering a wait from the Codex sandbox and recommended an execpolicy allow rule for one command, which it verified with a project-local rule under `codex exec` only.

Decisions by the author: use systemd for the waiter backend; drop the judgment-responder stage and "work while waiting" (called drift); write a design, not a ticket; the instruction route (each runtime's background facility, with a deadline) comes first and the waiter stays parked; one deferred ticket at the end, carrying the design and the audit as evidence; the main runner merges. The author rejected recommending a Claude Code-only solution and a "stage 0 then stage 2" recommendation.

Outputs: PR #1542 and the Linux platform contract ticket 1163 (sweep of Linux commitments; the contract itself landed through #1543, filed by another session); PR #1552 (queued-merge wait conditioned on the runtime waking the session, after the probes showed the earlier wording would park a Codex caller); PR #1553 (deferred ticket 1165, the parked waiter design, and an audit of long-run wait language with 7 contradictions, about a dozen gaps and 9 runtime leaks). Nothing of the waiter was built.

Review trail: an Opus seat (Agent token `opus`) reviewed draft v1 and corrected it (recorded outcome, resume gate, sequence). The merged PRs #1552 and #1553 were not run through `/gaze`; no review attribution record applies. Codex's description of its own wait tools (`exec_command`, `write_stdin`, exec cell with `notify()` and `functions.wait`, sub-agent completion) was relayed by the author and is self-reported, not exercised. The Pi packages `pi-longrun`, `pi-patty-bg-tasks`, `@mjakl/pi-processes` and `pi-bg-run` were read from their READMEs only.
