# The `zotero.py` helper

`"$IDH_ROOT/scripts/zotero.py"` (with `IDH_ROOT` resolved from the loaded skill) exposes the subcommands below. It is local-only and stateless: each call opens `zotero.sqlite` read-only and keeps nothing between runs. Every reading subcommand takes `--zotero-db PATH` and `--library L` (`user`, the default; `all`; or a numeric libraryID), and its output carries `read_mode` (see the end of this file).

- `probe <pdf>...` — JSON to stdout. Fields per PDF: `pdfinfo`, `page_count`, `first_pages_text`, `last_pages_text`, `identifiers` (doi/isbn/handle/arxiv), `year_hint`, naive `zotero_matches` (same shape as `match` output, fed from the raw pdfinfo title).
- `match [--title T] [--doi D] [--isbn I] [--arxiv A] [--handle H] [--author FIRST-AUTHOR] [--year Y] [--pdf P]` — deduplication lookup using the metadata *you* refined. Consults its keys strongest first — file content hash (`storageHash`, needs `--pdf` on disk) → persistent identifier (DOI, ISBN, arXiv, handle) → attachment filename → (first author, year, normalised title) → title Jaccard as last resort — and stops at the first key that fires. Output: `matches` (each hit carries its item `key`, `why` = which key fired, `certainty` = exact/strong/weak, attachment info, `pdf_basename_match`), a `verdict` (`match` / `ambiguous` / `none` / `unchecked`), and `consulted`/`skipped` so "found nothing" and "could not look" stay distinguishable. Scope defaults to the **user library** (the inject destination); a group-library copy does not count as already present — pass `--library all` or a numeric libraryID to widen deliberately. No database found → `verdict: "unchecked"`.
- `enrich (--item-key K --expect-title T --set FIELD=VALUE... | --jobs-file J) [--overwrite]` — reports the fields to fill on **existing** items; it never writes. See `references/enrichment.md` for the guards. Output: one row per item with `suggested` (`itemKey`, `field`, `old`, `new`), `refused`, and `status` (`suggested` / `nothing to change` / `not found`).
- `audit <dir> [--out PATH] [--ext ...]` — reconcile a staging directory against the library. Per file: `verdict` (`identical` / `work_present_with_file` / `work_present_no_file` / `ambiguous` / `absent`), the matched `zotero_key`/`zotero_title`, `why` (which key fired), `certainty`, and `consulted`/`skipped`; when several candidates tie at the top certainty tier (e.g. one md5 attached to two records), the row also carries `also_matches` naming every other tied parent (ticket 0570). Summary counts plus the action each verdict calls for on stdout; the full per-file report to `--out`.
- `reconcile [root] [--out PATH] [--apply]` — the BibTeX-aware audit of a repository; see `references/backfill.md`. Rows the library already holds without a file come back in `suggested_edits`.
- `attach --parent <itemKey> <file>...` — checks that the item exists and the files are readable, then reports the by-hand step (Add Attachment → Attach Stored Copy of File in Zotero). The repair for `work_present_no_file`; also how page-scan images or an HTML snapshot get filed under the work they belong to instead of becoming standalone items. It writes nothing: the connector cannot attach to an item it did not create.
- `inject (--entries-json J | --entries-file F) [--collection KEY] [--library L] [--dry-run] [--force] [--skip-corroboration]` — creates new items with their PDFs through the desktop connector; see `references/import.md`.
- `write --out <ris-path> --entries-json '<json>'` — writes the combined RIS. Each entry accepts: `type` (RIS code, default `JOUR`), `title`, `shortTitle`, `authors` (array; `"First Last"` is auto-converted to `"Last, First"`), `year`, `doi`, `isbn`, `issn`, `url`, `journal` (container title, whatever the type), `volume`, `issue`, `pages` (e.g. `"281-285"`), `numPages`, `publisher`, `place`, `number`, `genre`, `conferenceName`, `edition`, `seriesNumber`, `language`, `abstract`, `pdf`, `attach_pdf` (bool). Any other key is **refused**, not ignored — a misspelt key that silently does nothing is the defect this guard exists to prevent.
  - `number` is the type's identifying number: report number, patent number, standard number.
  - `genre` is the type's kind-of-thing label: `"RAND Paper"` on a report, `"PhD thesis"` on a thesis, `"Working paper"` on a manuscript.
  - `place` is the city of publication (`"Santa Monica, CA"`).

Zotero DB discovery order: `--zotero-db` flag → `$ZOTERO_DATA_DIR/zotero.sqlite` → `~/Zotero/zotero.sqlite` → `~/data/Zotero/zotero.sqlite` → `~/Documents/Zotero/zotero.sqlite` → parsed `~/.zotero/zotero/profiles.ini`.

Read modes. The script first opens the DB with `mode=ro`, which also reads the write-ahead log, where a running Zotero keeps its latest writes until a checkpoint (`read_mode: "ro"`). A running Zotero holds the file under an exclusive lock, so after a 2 s wait the script falls back to `immutable=1`, which reads the main file only and can lag the client (`read_mode: "immutable"`). Both modes are read-only. `inject` needs Zotero running, so it usually reads the lagging snapshot and says so in a `warning`; `dedup-report` refuses a locked database whose WAL is non-empty.
