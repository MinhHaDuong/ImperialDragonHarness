# Submission Checklist

Pre-submission verification list. Review each item before final submission.

## 1. CFP Compliance

- [ ] Submission type matches project scope and maturity
- [ ] Submission type is strategically appropriate for acceptance probability
- [ ] Word/page count within specified range
- [ ] All required sections present
- [ ] File format correct (PDF, DOCX, etc.)
- [ ] Deadline confirmed (note timezone)
- [ ] Review criteria identified and addressed

## 2. Fit Assessment

- [ ] Project scope aligns with conference themes
- [ ] Contribution type matches venue expectations
- [ ] No overreaching claims relative to format
- [ ] Claims and evidence are aligned

## 3. Content Structure

- [ ] Research question explicitly stated
- [ ] Approach/method clearly described
- [ ] Main analytical outcomes or contribution elements clearly presented
- [ ] Significance/implications articulated
- [ ] No excessive detail, tables, or figures
- [ ] No promotional language

## 4. Citations

- [ ] Citations style matches venue requirements (Chicago, APA, MLA)
- [ ] All references cited in-text
- [ ] No orphan references in bibliography
- [ ] Self-citations appropriately framed
- [ ] Foundational works and direct precedents prioritized

## 5. Anonymization if CfP requires Double-Blind

- [ ] Author names removed from signatures and text
- [ ] Affiliations removed
- [ ] Self-citations in third person ("The authors previously showed..." → "Previous work showed...")
- [ ] Project names anonymized if identifying
- [ ] Acknowledgments removed or anonymized
- [ ] Document metadata cleared (author field in PDF/DOCX properties)
- [ ] Figures contain no identifying information

## 6. Review Simulation Check

- [ ] Editorial Gatekeeper concerns addressed (compliance, clarity, format)
- [ ] Contribution Evaluator concerns addressed (positioning, novelty)
- [ ] Risk Evaluator concerns addressed (vulnerabilities, fragile claims)
- [ ] Convergent issues across reviewers resolved

## 7. Quality summary

- [ ] Abstract is self-contained (readable without supporting materials)
- [ ] Key claims supported by evidence or citations
- [ ] Contribution clearly positioned (infrastructure, method, application, critique)
- [ ] Limitations acknowledged where appropriate

## Common Pitfalls by Venue Type

### Digital Humanities (EADH, DH, ADHO)

- Poster abstracts are evaluated as short papers
- Technical infrastructure contributions are valued
- Interdisciplinary framing expected
- Reproducibility and openness noted positively

### Computer Science (ACL, EMNLP, NeurIPS)

- Novelty claims must be substantiated
- Baselines and comparisons expected
- Code/data availability increasingly required
- Limitation sections now standard

### Social Sciences (APSA, ASA, ISA)

- Theoretical framing essential
- Policy implications valued
- Case selection must be justified
- Generalizability discussed
